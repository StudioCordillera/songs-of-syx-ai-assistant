# Candidate native appearance controls

This unshipped, Codex-authored follow-up adds a **Style** control to the [native chat candidate](NATIVE_CHAT_LAYOUT.md). It reuses the earlier completed Claude prototype findings; an existing local CLI process was not established idle, so no overlapping invocation or new Claude review is claimed. The production simple Pro panel, both tested bundles, normal game/profile, keys, saves and histories remain unchanged.

Style replaces the chat-choice strip temporarily with Forest, Parchment and Night presets, a separate seven-character accent input and Apply accent. Clicking Style again returns to the chat choices. The question composer and color input are separate objects; editing a color never sends or consumes a question. Choosing a preset restores its accent. Custom accents accept exactly six hexadecimal digits with an optional `#`, canonicalized to uppercase. Invalid text preserves the prior palette and shows a plain correction while Style is open. Appearance hints stop masking helper status when the form closes.

The palette affects our panel background, own transcript/status text and launcher/header/resize surfaces. Engine-owned button, input, selection and slider styles retain their normal game appearance. Only our own color objects change; no global game theme is mutated. Style changes are explicitly **for this run** and do not write the geometry preference file. Persisted appearance, selected-preset/keyboard/accessibility refinements and a stable production preference path remain work.

`PanelTheme.java` chooses black or white own text using a detached sRGB contrast calculation. A finite grid of 4,096 custom colors satisfies the abstract 4.5 ratio against its selected ink, and preset body/accent pairs are checked separately. This is **not native pixel contrast, WCAG certification or a complete accessibility review**. The installed public `COLOR` constants call 127 normal white and 255 doubled white; candidate RGB channels are mapped to 0..127. Public `ColorImp`, own `GText` coloring and native compilation are source-pinned in the evidence. Texture/gamma/color management, physical display settings and rendered readability remain unverified, as do other fonts/scales. These are shipped-source/compiler checks, not a separately documented stable styling contract.

[NATIVE_CHAT_APPEARANCE_VALIDATION.json](NATIVE_CHAT_APPEARANCE_VALIDATION.json) records nineteen native layout checks. The two new cases route real own Style/preset/Apply controls at the proposed 640×560 minimum, check all top-level bounds, pairwise form-control separation and separation from the transcript, preserve the question draft/composer, refuse an invalid accent, apply `#abcdef` as `#ABCDEF`, retain geometry-file bytes and release the color input's own focus marker when Style closes. Earlier seventeen checks repeat against the changed panel, including geometry persistence, normal Send/Stop and lifecycle/viewport cancellation. Supplied launcher/resize primitives remain distinct from physical/native input.

A fresh seven-phase real production coordinator/default MCP/disposable SQLite run also changes to Parchment while a simulated reply is pending, then checks resize, real partial-frame/draft retention, open/closed progression, completion/reopening and Stop. The external provider factory remains fake: no key is read and no inference is sent. The panel model/IPC, control bounds and render callbacks prove neither unobscured display, human reading nor physical keyboard/focus acceptance. No badge, receipts, typed chips or gameplay commands are added; unknown/oversized display remains unread under the separate policy.

The evidence records exact sources, selected installed public styling source hashes, compiled own classes, explicit clean completion, zero exit/no known crash markers, copied-mod restoration and copied-save integrity. Earlier layout/viewport/background/preferences reports keep their original dates/hashes. The current player ZIP/source check still passes without a production rebuild.

# Automatic preferences across two native game launches

`dev/run_native_chat_auto_restart.py` now validates the candidate's automatic preference path across two actual sequential copied-game JVMs. Both select the **same assistant state directory**, with no candidate preference-directory property. The version-2 preference file stays in place between launches: device/inode, content hash, modification time and permissions are unchanged during inter-launch preparation. No preference copy, migration or manual panel configuration substitutes for automatic startup.

The first native startup is Forest/840×640. Its own Style and resize controls save Parchment/#745137/880×660. The second constructor restores that geometry/style before interaction, then completes the independent existing workflow and grows to 920×680. Both native initial-layout records report automatic selection and successful configuration. [NATIVE_CHAT_AUTO_RESTART_VALIDATION.json](NATIVE_CHAT_AUTO_RESTART_VALIDATION.json) pins fourteen phase checks across two real default-MCP/production-helper/SQLite workflows, with fake inference only.

The wrapper holds the shared native fixture lock for both launches. After the first runner fully exits/restores its copied mod, the wrapper archives **all other** disposable fixture artifacts: history, IPC, markers, classes and reports remain recoverable in a private sibling directory. Only the existing preference file remains in the same state directory. The second helper/history are fresh; this is not same-history/provider continuation. The copied game/profile/save are intentionally common. No normal assistant root, credential or normal save is selected.

An internal runner seam admits only caller-owned mode-0700 directories below repository runtime, empty or containing only a regular caller-owned mode-0600 fixed preference file. Other cases, links, unexpected artifacts and public preference modes refuse. No public arbitrary state-directory option is added. The bounded archive refuses an existing destination, links or more than 128 top-level artifacts; it preserves preferences and moves other entries without discarding them. Seven offline cases cover this admission/preservation scope, alongside the existing root-path guard tests.

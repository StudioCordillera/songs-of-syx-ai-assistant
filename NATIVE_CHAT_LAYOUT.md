# Native chat layout candidate

This is an unshipped, Codex-authored port of the real simple `ChatPanel`, informed by the completed [Claude prototype critique](CLAUDE_PROTOTYPE_REVIEW.md) and [input/visibility boundaries](CHAT_VISIBILITY_BOUNDARY.md). It replaces our own panel class only inside a disposable developer fixture. The tested player ZIP, normal game and private histories remain unchanged. No new Claude generation or source approval is claimed: an existing local CLI process was present and not established idle, so no overlapping invocation was started.

Unlike the earlier empty [gesture surface](NATIVE_GESTURE_SURFACE.md), this candidate contains the current automatic-connection/session/filter/transcript/composer/Send/Stop logic and actual public native controls. The simple interface remains Pro; advanced/provider controls are unsupported by this candidate and its constructor refuses advanced mode. It has a short-click launcher, held launcher drag, immediate header drag and a resize grip. Empty content does not initiate dragging. Header and grip have separate hit areas above/below real controls.

## Layout and refresh behavior

The initial panel is 840×640 in internal UI coordinates, with a proposed 640×560 minimum. Composer width/wrapping, transcript viewport and footer positions follow the own rectangle. The same composer object and its 240-character capacity survive reflow; existing per-chat draft/history logic stays intact. The candidate fits to public internal native dimensions, which are distinct from the virtual display size. Reset explicitly restores the candidate defaults. The later [preference follow-up](NATIVE_CHAT_PREFERENCES.md) adds explicit disposable geometry persistence. The later [appearance follow-up](NATIVE_CHAT_APPEARANCE.md) adds this-run presets and a separate custom-accent form. Explicit version-2 candidate preferences can now persist style; no automatic player configuration, target chips or unread badge is implemented.

Only a semantic helper-state change rebuilds the open panel. A heartbeat-only update preserves its existing controls and an active gesture, instead of rebuilding every second. New text/chat/status/list content cancels capture before rebuilding. Resizing deliberately retains its own capture across reconstruction. Close, manager removal, underlying-view changes, hidden UI and the detached reducer's bounds/timeout policies cancel capture. Its five-second limit is recovery, not a reliable native focus-loss signal.

The original outgoing protocol-2 actions and synthetic incoming frames remain distinct from model/game evidence. Normal Send encodes the selected chat/session/question; Stop queues its own action. Local opening/closing does not itself add a new game-control or receipt protocol. No render callback clears unread state.

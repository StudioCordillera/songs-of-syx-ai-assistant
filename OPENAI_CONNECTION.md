# OpenAI subscription connection: prepared, not yet connected

This app has an independent public-client Sign in with ChatGPT implementation and a mocked stateless Responses transport. Neither is connected to the in-game provider picker yet. No OpenAI token record or successful subscription inference has been established. DeepSeek/Claude evidence in CHAT_VALIDATION.json is separate.

`syx-chatgpt-login` starts the official registration flow for **Songs of Syx AI Assistant**, with a stable local host ID, fresh state/nonce and PKCE. The browser asks to share basic profile data and permit ChatGPT plan usage. This is new app access, not reuse of the Codex application's credentials. Credentials are saved only after verifying the official signature, issuer, audience, expiry, nonce, expected account and granted plan scope. Declined/invalid callbacks never save tokens. See the official [registration/sign-in contract](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).

Install `.[openai-auth]` for explicit JWT/crypto dependencies. Default auth storage is `~/.local/share/syx-assistant-auth`, outside game exports and chat histories, protected with user-only permissions. The temporary callback listener binds only IPv4 loopback `/auth/callback` and closes after success, denial or the five-minute attempt limit. It suppresses request logging and never prints codes or tokens. Keep the issued client/account pairing for later sign-ins; the dynamic registration entrypoint is not an issued client ID. Account selection, refresh, revoke and complete in-game setup still need implementation.

`syx_openai_plan.py` uses the account-specific model catalog and the public Responses endpoint with `store:false`, streaming and namespaced function tools. Private response continuation remains in memory. Failed/incomplete/missing terminal events are errors; there is no API-key or private `backend-api` fallback. Its protocol tests are mocked. The official [model/inference contract](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) and [preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) govern that route.

Next steps require approval of the displayed account-access grant, a validated connection, account-bound model selection and tool-loop/UI wiring, followed by authenticated game tests. Account changes must not silently forward an old conversation. No completion claim is made for this route.

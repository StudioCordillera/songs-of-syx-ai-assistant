# Roadmap

Current boundary: an in-process SCRIPT mod, typed public-API observations, bounded snapshot selections and cited reference retrieval. No private reflection or native/OS UI automation. See API_BOUNDARY.md.

1. Expand explicit data mappings with primary-source provenance, meanings, units and per-version coverage. Leave inaccessible data unavailable.
2. Extend the established partial UI context and evidence catalog. Selected subject/view/known-overlay/room-blueprint reads, named individual statistics and bounded exposed popup/section content are implemented. Exact selected room instances, tooltip text, management tabs and panel ordering require appropriate public APIs.
3. Establish a documented unload-to-menu lifecycle hook or keep the freshness limitation explicit; test menus/transitions and large settlements.
4. Extend reviewed official/developer reference coverage and version-aware search.
5. Build an in-game chat client using supported OpenAI authentication, subject to registration/eligibility.

Full game state, all-menu coverage and a fully documented stable mod API are not currently available.

On-demand entity requests are implemented in 0.7.0: fixed public fields and named individual stats, bounded filters/cursors, update-thread evaluation and request/session/tick provenance. The isolated over-1,000-entity fixture passes. Next data-access work is stable bounded multi-page observations, broader typed non-entity schemas, attribute meanings/units and large-city performance. Current paging is mutable across responses, and no complete game-state schema is claimed.

0.8.0 checks both editor activations and deployment-to-retreat restoration, and exposes bounded public popup/section content. Remaining UI work requires further typed public mappings and runtime evidence; private panel enumeration, exact room/tab/tooltip readers and lifecycle/result callbacks still need appropriate public APIs. Stable multi-page data selection remains separate unfinished work.

0.9.0 exposes scene division status and latest hover-consumption flags, and checks running battles plus controlled victory/defeat restoration through public game UI dispatch. Source/private result content remains unavailable; no action API is shipped. Further work includes stable bounded selection across pages, broader typed variable/relationship mappings, unit/mechanics evidence, full world/editor workflows and naturally occurring campaign transitions.

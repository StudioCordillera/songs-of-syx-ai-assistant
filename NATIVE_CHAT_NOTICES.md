# Native helper recovery-notice integration

The fixed developer `layout-notices` fixture now connects the [recovery-notice Coordinator subclass](CHAT_RECOVERY_NOTICE_CANDIDATE.md) to the current [scrollable native panel candidate](NATIVE_CHAT_STATUS.md) through real plain IPC2 files. It retains the default read-only MCP, actual production conversation/history lifecycle and two deterministic fake providers. This is an unshipped own-class overlay, with no production source or player bundle change.

The existing nine phases first cover automatic connection, a pending partial reply with style/resize/draft preservation, unpaused open/closed progression, closed completion, reopening, Stop, graceful same-history Coordinator/SQLite recovery and completed Send-ID deduplication. Two additional phases then check actual helper-generated notice text in the native panel's wrapped status model:

1. The verifier explicitly authors a running turn in disposable history **without requesting inference**, gracefully stops the coordinator task and reopens SQLite with the production startup recovery option. The stored turn becomes interrupted. Native automatic sync selects the chat again; the actual candidate helper emits **Earlier reply interrupted; no automatic retry.** The panel retains the same composer/draft, selected chat, geometry and Parchment style.
2. A fixed injected current-game admission callback raises a labeled fixture error after the production dispatcher commits a new action ID but before it creates a turn. The normal callback is restored before replaying that identical request. The journal deduplicates it, the candidate emits **Earlier Send outcome unknown; no automatic retry.**, and native rows receive that text without entering generation or losing the draft. No new task, turn, event or provider is created by the duplicate.

These are **authored local-history/admission setups**, not crashes or pending paid requests. The game, verifier process and stdio MCP remain live; only coordinator tasks/connections are gracefully replaced. Separate [owned-process SIGKILL checks](CHAT_PROCESS_RECOVERY.md) retain their own scopes. An old journal acknowledgement has no payload/outcome metadata and cannot prove delivery, failure or billing truth.

[NATIVE_CHAT_NOTICES_VALIDATION.json](NATIVE_CHAT_NOTICES_VALIDATION.json) records eleven native checks, exact source/compiled-overlay hashes, one completed/one cancelled inferred turn plus one authored interrupted turn, exactly two providers/four fake rounds and two actual original-reference calls with immutable citations. The provider factory refuses a third instance. A fresh nine-phase `layout-recovery` run verifies the shared notice-disabled base path separately. Full offline checks and unchanged source-matched current/previous player ZIPs are recorded; no paid inference is used.

The internal viewport remains 1536×768. Own supplied launcher/resize primitives and public own Send/Close/Stop routing do not constitute OS input, engine pointer mutation or screenshots. Wrapped native model rows prove neither rendered/unobscured text nor human readability, physical scrolling/focus, all-font/scale accessibility or read receipts. The long synthetic status/minimum-bound check retains its separately pinned twenty-two-check layout report; it is not relabeled as this new helper run. Unknown/oversized replies remain unread.

# Standalone player chat design review

[Open the prototype](design/player-chat-prototype.html) locally in a modern browser. It is dependency-free and clearly labeled simulated; it reads no game, calls no provider, loads no external assets and changes no normal histories or saves. Reload resets its mock conversations, drafts, timers and layout. This is not the native mod or a replacement for the tested player ZIP.

This reference prototype was authored by Codex using the four recovered Claude source reviews in [CLAUDE_UX_REVIEW.md](CLAUDE_UX_REVIEW.md) and the newer display/input findings. It is **not a completed Claude-generated design response**. A subsequent completed [local Opus 5.5 peer review](CLAUDE_PROTOTYPE_REVIEW.md) informed the pointer, focus and reconnect fixes. Separate local Opus/max generation outcomes belong in [CLAUDE_UX_COLLABORATION.json](CLAUDE_UX_COLLABORATION.json); do not infer success from starting a CLI process.

The layout keeps the player's question and transcript central, with a quiet current-load/history drawer and automatic connection status. The closed launcher carries completed-reply counts; it hides while the panel is open so it cannot cover Send. Launcher hold/slop dragging, immediate header dragging and a resize grip have keyboard alternatives. Appearance offers forest/parchment/night presets and custom accents adjusted for readable contrast. Drafts belong to individual mock chats. Next-message chips distinguish typed person/tile targets from unsupported/stale selections.

Delayed simulated replies continue while closed. Opening does not clear unread messages. An explicit read control checks that the complete reply card is inside the transcript, with other own menus closed and page focus/visibility valid; clipping/unknown conditions refuse. This browser policy does not establish a native game visibility contract. Stop cancels the simulated timer without inventing a completed reply. Disconnect shows unknown counts rather than zero. A simulated new load keeps earlier messages/targets historical; it does not invent a permanent world identity.

[Browser review evidence](PLAYER_CHAT_PROTOTYPE_VALIDATION.json) distinguishes iterative manual checks from the subsequent appearance-only changes. Checks include a closed-panel badge, explicit read/focus, separate drafts, unsupported/stale targets, cancellation, load filters, unknown connection state, keyboard geometry and custom-color correction. Only one desktop viewport was inspected. A subsequent actual header-drag/resize and stationary-launcher-hold browser recheck is recorded separately. Held launcher movement, out-of-window release, all resolutions, touch/screen reader, persisted migration, provider, native widget and game acceptance remain unverified. The implementation is a review candidate, not production-ready UI.

Before a native port: use the completed compact Claude review and retained findings instead of repeating full generation; choose the stronger interaction concepts against evidence; establish public own-widget hit testing/focus/cancel and layout bounds; integrate paired bounded display/receipt transport with matching applied responses; retain whole-message provenance and avoid automatic clearing from render callbacks. Add target chips only from supported typed observations, never inferred hover/selection. Complete exact-source native/Pro/core/distribution checks and promote the paired player bundle once the port passes. Keep [the tested download](releases/README.md) available throughout.

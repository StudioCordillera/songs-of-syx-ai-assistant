# Candidate chat layout preferences

This is an unshipped extension of the [native layout candidate](NATIVE_CHAT_LAYOUT.md), authored by Codex using earlier completed Claude findings. No new Claude source review is claimed: an existing local CLI process was not established idle. The production constructor, tested player JAR/ZIP, normal profile, saves, key and histories remain unchanged.

The candidate has an explicit `configureCandidatePreferences` seam for a caller-owned directory. The fixed native fixture configures only its disposable runtime directory. There is no automatic production path, per-world identity, history migration or new MCP/action tool. Future player integration must choose the private stable configuration directory and validate restart/multiple-load behavior before shipping.

`PanelPreferences.java` stores only version 1 and the eight integer panel/launcher coordinates and dimensions in `chat-layout.preferences`. No question, transcript, session, provider, key, theme or target is stored. Each file is at most 512 bytes; coordinates are 0..8192 and dimensions 1..8192. Duplicate, missing, unknown, non-ASCII, malformed and unsupported-version fields refuse the entire record. Geometry is fitted to the current accepted internal viewport on loading, retaining the candidate's minimum/fallback policy.

Explicit gesture drops and Reset write preferences. Automatic viewport clamping, helper refresh, opening and closing do not write them. A smaller display therefore does not silently overwrite the saved layout. Loading is bounded through a non-following channel; missing files use the current defaults, while malformed files preserve current geometry and remain untouched. Reset can explicitly replace malformed preferences after the directory has been successfully configured. A failed save leaves the changed layout usable for this run and shows a plain notice; a failed load also shows a notice. No automatic retry loop or blocking file operation on every update is added.

Saving uses a private mode-0600 temporary file in the same existing directory and atomic replacement, with cleanup on failure. Unsupported atomic moves/POSIX permissions refuse rather than falling back to a partial overwrite. Static file/directory symlinks and nonregular files are refused; replacing a regular hard link leaves its other link unchanged. These finite checks do not establish a hostile concurrent filesystem/race-security boundary, crash/power-loss durability, all-filesystem portability, non-Linux support or universal game-thread I/O cost. The caller must own and protect the configuration directory.

## Evidence

[NATIVE_CHAT_PREFERENCES_VALIDATION.json](NATIVE_CHAT_PREFERENCES_VALIDATION.json) records seventeen native layout checks: the previous fourteen plus explicit save/reload, no write on automatic clamp, and malformed-load preservation/explicit Reset. The unchanged composer object/draft and current fitted geometry are checked. Sources and compiled own classes are recorded separately from the base released JAR; source hashes are frozen before compilation and verified afterward.

The standalone `test_panel_preferences_java.py` compiles the detached code and runs seventeen named format/filesystem cases under pytest's temporary directory. Cases include exact bytes, unknown versions, duplicate/unknown/missing fields, integer/size/ASCII bounds, missing/default files, fresh reads, private atomic replacement, preserved oversized input, directory and symlink refusal, other-hard-link preservation and temporary cleanup. These are real temporary filesystem operations without game/provider/credentials, rather than simulated successful writes.

A fresh seven-phase real-helper background fixture also passes with the changed panel and preference class compiled. It uses the production coordinator/default MCP/history and fake inference, checks open/closed progression, real partial-frame/draft retention, completion/reopening and Stop. That fixture leaves preferences unconfigured; it revalidates the changed panel integration but does not claim automatic preference loading in the player. The earlier [background report](NATIVE_CHAT_BACKGROUND_VALIDATION.json) retains its original date/source.

Native gesture dimensions/inputs remain supplied owned primitives, not OS or engine pointer/button injection. Public own Send/Close/Stop/filter/Reset routing, clean completion, zero exit/no crash markers, copied-mod restoration and copied-save integrity are separate from physical input/focus, unobscured display, human reading, real-model/network, all-scenes, custom colors, badges and receipts. No render callback clears unread state. The candidate's layout persistence is incomplete player work until path/lifecycle/restart, focus/scale/accessibility and paired release gates pass.

Reproduce the seventeen native checks with `dev/run_native_chat_layout.py` and the separate background checks with `dev/run_read_fixture.py --case layout-background`, using [the licensed-game/copied-save/Java/JDK workflow](CONTRIBUTING.md) under an isolated display. Both honor the machine-wide native fixture lock. Offline tests require a complete JDK and no game or key.

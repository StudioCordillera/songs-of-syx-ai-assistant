# Mod-owned gesture candidate — not shipped

`dev/chat_gesture_candidate.py` and the detached Java `GestureReducer` reconcile the older reducer with accepted interaction findings from [the completed Claude prototype review](CLAUDE_PROTOTYPE_REVIEW.md). Neither is imported/packaged by the player. This is a Java policy port with synthetic cross-language checks, not a native widget, Claude-generated implementation, input or visual acceptance result.

The future adapter must classify an actual mod-owned launcher/header/empty chrome/resize handle and copy pointer/button primitives through reviewed public routes. The reducer does not discover those surfaces, poll input, establish window focus, identify game objects or control the game. Composer/citation/button/scroll/game labels cannot begin capture; native hit-testing correctness remains separate.

## Reconciled interaction policy

- A short stationary launcher press toggles once on release. A 350-ms engaged hold suppresses opening even without motion and exposes `armed` state. A movement exceeding six Euclidean coordinate units before engagement locks that gesture into `blocked`; waiting longer or returning to the press point cannot turn it into a late drag/click. Engaged movement starts a drag, and dropping never toggles.
- Nonzero own header/chrome/resize movement starts immediately, without launcher slop. This implements the stronger reviewed interaction policy while retaining bounded geometry/cancellation from the earlier reducer. The candidate is not identical to browser event/timer ordering: supplied monotonic samples decide engagement, and a release alone cannot reconstruct missed held movement.
- Position/size remain within the supplied internal viewport. The candidate 480×320 minimum shrinks when less space remains at its origin. These are unaccepted native layout/font requirements; the browser reference uses a different height minimum. Geometry is computed from the original press rectangle rather than accumulated deltas.
- Cancellation occurs on own-surface deactivation, viewport change, out-of-bounds pointer, explicit cancel or a five-second total timeout. The timeout is a conservative recovery policy, not window-focus proof, and can interrupt a deliberate long drag. A cancelled result supplies no new rectangle; applying or restoring prior layout belongs to the future adapter.
- Invalid/non-finite/coerced samples, malformed viewport, backwards time and nested capture are refused without changing the last valid capture. Oversized Python integers now fail as validation errors. Java APIs use typed primitives; the test-only trace adapter requires explicit Boolean strings.

The inspected public native pointer can remain stale out of bounds or when unfocused, and the inspected focus getter is private. [Input boundary](CHAT_INPUT_BOUNDARY.md) and [visibility boundary](CHAT_VISIBILITY_BOUNDARY.md) remain gates. No private fallback or display/read receipt is introduced.

## Evidence and reproduction

[Java/Python evidence](CHAT_GESTURE_JAVA_VALIDATION.json) records 2,039 finite trace steps across 200 seeded scenarios, with 26 independently authored expected outcomes. Tests exercise short-click/hold/early-motion lockout, immediate small header movement, clamping, release, bad samples preserving capture and cancellation. Compilation targets Java 16 using only the JDK and these two own Java sources, without game classes. Matching implementations do not independently prove every policy; the explicit expected outcomes and separate Python cases provide additional finite checks.

With a complete JDK 17+ and `java` available, run `.venv/bin/python dev/verify_gesture_reducer.py --output-dir runtime/gesture-check`. `SYX_JAVA_HOME` may select the compiler's full JDK. The trace adapter in `GestureTrace.java` is test tooling, not a production IPC or arbitrary invocation lane. Tests use detached synthetic coordinates, no game/provider calls, credentials, normal saves, native input or screenshots.

The earlier [25-case report](CHAT_GESTURE_CANDIDATE_VALIDATION.json) retains its original source/date scope. That reducer toggled a stationary long hold, required header slop and allowed late dragging after early movement; the current policy deliberately supersedes those choices. The retained browser review informs this reconciliation but has not peer-reviewed the new Java source. Existing local Claude CLI sessions were present and not established idle, so no overlapping new review was launched; [collaboration evidence](CLAUDE_UX_COLLABORATION.json) records the deferral without claiming a model/quota gate.

Next: a bounded focused peer review when the CLI is available; a source-reviewed own-widget adapter with native ownership/cancel/scene/scale/focus evidence; then actual paired player/Pro/core/distribution acceptance before shipping. Theme, layout persistence/reset, typed attachments and unread display receipts remain separate work. The latest and previous tested player ZIPs stay unchanged.

# Cited-guidance regression checks

Run `.venv/bin/python dev/verify_guidance.py --state-dir runtime/guidance-check` from the repository. This starts the actual stdio MCP server and calls `search_guidance`; no running game, provider request or credentials are required. Use a new directory to evaluate the starter corpus independently of local edits. Existing corpus records are preserved by the seed installer, so the report records the evaluated corpus size and checksum.

`guidance-questions.json` contains 37 authored cases. The initial ten player questions cover nine starter summaries; one unrelated question must return no evidence. Four version probes check exact version, family version and two mismatches. Three authority-filter cases check official, developer and community results. Two additional authority-filter queries must return no results rather than substituting unrelated evidence. Nine added cases cover two reviewed V71 topics, version inputs and official-only filters (REFERENCE_EXPANSION.md). Eight further cases exercise historical developer routing/display explanations, evidence boundaries, developer-only filters and unknown compatibility for exact/family/later versions (HISTORICAL_REFERENCE_REVIEW.json).

Each positive case specifies a narrow advice expectation, the direct citation URL, speaker, authority and compatibility label. It also names supporting fragments that must be present in the returned **body**, and caveats that must remain in the body or version notes. Title matches alone cannot pass. Case expectations are authored from the existing reviewed summaries; new source review is recorded separately in REFERENCE_SOURCE_REVIEW.json; the local evaluator itself does not fetch or re-review web sources. The transport-loop case checks that warning separately from warehouse collection settings.

The report preserves query/version/filter, citation, advice expectation, check counts, returned-body hash, evaluation time, corpus hash and exact evaluator/runtime hashes. It checks response size as well. Negative tests remove support or caveats and change citation URL, author, authority or compatibility to ensure an otherwise correctly ranked record fails the evaluation. A no-result expectation also rejects unrelated evidence.

## Review limits

Literal fragment checks detect missing evidence and caveats. They do not establish semantic entailment, validate a model's complete answer, prove that a guide is optimal, or turn old developer comments into current mechanics. A person must review the advice-to-passage relationship when changing an expectation. Keep recommendations narrower than their evidence, distinguish community recommendations from developer statements, and preserve unknown patch compatibility.

This is a small local retrieval regression set, not an independent search benchmark. Multiple cases reuse sources; case count is not unique source count. The evaluator performs no live web refresh and does not establish continued page availability. New primary-source review and broader topic coverage remain roadmap work. Source retrieval dates retain the prior review dates; re-running this evaluator must not refresh them.

The local evaluator makes no inference or game calls. The reference-expansion checkpoint separately validates and bundles its changed runtime modules; existing copied-game scene evidence retains its exact recorded scope. See REFERENCE_EXPANSION.md and USER_TEST_VALIDATION.json.

The historical-reference expansion contains 13 summaries. Its 37 actual MCP cases check 52 supporting fragments and 39 caveats. The two newly reviewed developer threads add historical troubleshooting context, not current-patch mechanics or executable game APIs. An upgrade from the preceding eleven-record corpus preserves existing bodies, local edits and review dates while adding both summaries.

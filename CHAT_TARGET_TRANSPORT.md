# Target drafts across the existing MCP connection

`dev/chat_target_transport.py` closes the earlier same-process-only gap for the **developer candidate**. `McpTargetDrafts` uses one initialized caller-owned MCP `ClientSession`, the existing `game_status` endpoint and three existing retained-page readers. It shares detached validation, page hashes, limits and draft handling with [the local target candidate](CHAT_TARGET_CANDIDATE.md). Nothing is imported or packaged by the playable mod. There is still no native picker/chip protocol, coordinator integration, durable accepted-turn evidence or provider dispatch.

The adapter never launches a server, reconnects, creates a new capture, invokes a user-supplied tool name or retries a request. The caller must create a capture using that **same** initialized session before explicitly selecting its token/page. Four required tools must advertise read-only and idempotent annotations. Runtime/version and the complete exported scene are checked before/after preparation; every original page is read again and compared byte-for-byte. Staging also checks status after its page read. These checks retain the existing recent-export freshness window and historical capture semantics; they cannot freeze the game or prove every transition between exports.

Each stage/prepare operation has one five-second deadline covering admission, status, page reads, final status and waiting for the draft lock. Draft mutations serialize across async operations. Cancellation propagates without clearing a draft, and timeout/disconnection has no automatic retry or capture. Preview is a detached synchronous historical view; it does not poll liveness. Remove also waits for the same bounded lock. This is a candidate responsiveness policy, not native UI acceptance. SDK/session lifetime belongs to the caller; a replacement server requires a new session/adapter and explicitly selected new captures. Foreign/evicted/expired tokens fail rather than being silently reconstructed.

Accepted response bodies are limited to 64 KiB, whether delivered as structured MCP data or a single JSON text content block. The adapter checks canonical capture UUID, requested offset, row count/continuation, kind/completeness where exposed, fresh same-context status and required original provenance. Unknown/null projected row fields are preserved; malformed metadata and non-finite values refuse. Final attachment envelopes retain the 32-KiB/eight-chip/100-chat limits. The 64-KiB check occurs **after SDK transport parsing**; this is not a raw JSON-RPC frame allocation bound or protection against an untrusted server consuming process memory. The intended peer is our local pinned server.

`dev/target_transport_fixture.py` starts the actual production eighteen-tool MCP server with three explicitly synthetic capture-reader functions and a disposable snapshot. It does not load the game or provider. `test_chat_target_transport.py` drives real child stdio sessions to check all three kinds, original provenance, four fixed reader calls with no recapture, independent-server token refusal, pool eviction, observed runtime change, cancellation/timeout recovery, disconnection, read-only admission and malformed/oversized responses. [Evidence](CHAT_TARGET_TRANSPORT_VALIDATION.json) pins final source and finite scope. Real stdio transport with synthetic rows is distinct from licensed-game MCP acceptance, production IPC, native UI or paid Pro tests.

The next integration needs an owned long-lived MCP connection shared with the coordinator's tool loop, bounded native target selection requests, immutable evidence persisted with the accepted turn, exact queue acknowledgement, send/cancel races and lifecycle tests. A prepared envelope must never be treated as a game command or as proof that its target is still live after asynchronous waits. Keep the source-matched tested player bundle intact until the complete paired path passes its native/provider/release gates.

## Focused local Claude review

A broader local Opus/high request ended with an error because its response exceeded our configured 4096-output-token budget; it returned no usable critique. A subsequent narrower cancellation/draft/byte-limit review used an 8192-token response budget and **completed on claude-opus-5-5** in 31540 ms, one reported turn. Neither attempt hit a new account quota/model gate, purchased credits or bypassed limits. These are bounded source reviews, separate from game/provider tests; the final follow-up source was not reviewed again.

The completed critique correctly separated post-receipt payload checks from a raw SDK allocation bound. That limitation is explicit above; SDK framing metadata is outside the selected evidence-payload budget. We also added bounded handling of structured/text duplicates, rejected conflicts, converted JSON recursion failures into actionable ValueErrors (no universal fixed nesting-depth limit is claimed) and made remove timeouts consistent. The suggested age/hash concern was conditional rather than a reproduced defect: `observed_page` already strips dynamic ages before exact-byte comparison. We retained that stronger equality check, moved it behind a shared draft verification method, and tested changed age/retention metadata explicitly. [CLI metadata](CLAUDE_UX_COLLABORATION.json) pins the actual input/outcomes without publishing raw streams or internal thinking.

## Copied-city public-getter follow-up

The `tiles` case in `dev/run_read_fixture.py` additionally drives this developer adapter over actual MCP and the unchanged published mod JAR. Two retained tile rows match independent public-getter fixture expectations. Initial stage/prepare leaves the tile request mailbox unchanged. Preparation refuses a changed active world view without losing its draft, recovers when the copied city view is restored, refuses the naturally evicted original token and accepts an explicitly chosen replacement capture. The existing tile/scene checks still run, including actual reload invalidation. This uses the shared native fixture lock, isolated Xvfb/copied profile and copied save; fixture-only public view/speed actions remain separate from the read-only adapter.

The final runner requires a clean exit, no known engine crash markers, copied-mod restoration and unchanged copied save. [Transport evidence](CHAT_TARGET_TRANSPORT_VALIDATION.json) pins the exact source/JAR and retained native report hash. This validates a finite **tile** path; entity/regional transport checks remain synthetic, and native chips/picking, input/focus, durable enqueue and real inference remain unimplemented. No normal saves, screenshots, OS game input or provider calls are used.

Retain the real previous tested bundle. A design prototype or simulated provider is never release acceptance.

The selective-state, truthful lifecycle and high-quality references objectives continue throughout this revision. Cached viewport production DTOs remain a useful dependency for explicit area attachments, but cached geometry never identifies a hovered/selected object or all visible tiles.

## First backend candidate design constraints

- Migrate history transactionally without rewriting old event/session identities. Store player-assigned world groups separately from runtime sessions; an unknown runtime remains ungrouped until a reliable public identity or explicit player association exists. Apply SQL filters before the existing 100-chat limit. Moving a conversation's current attachment must not erase the provenance of earlier turns.
- Derive unread successful replies from final visible assistant events joined to completed turns, with a persisted per-chat read acknowledgement validated by a unique event ID. Database integer sequences can be reused after deletion; a sequence alone cannot authenticate which chat/event was displayed. The existing loop appends its final event and then finishes the turn in separate transactions; an event alone is not sufficient proof of completed status. Streaming/tool events and partial cancelled/failed replies cannot inflate the badge. A display acknowledgement must identify the chat, session and individual actually displayed final event UUIDs, not acknowledge an unseen newest event automatically.
- Use fresh bridge status to establish the active runtime; do not trust a session UUID from an arbitrary UI request as an authoritative game switch. Automatically start/select a current-runtime chat, retain old histories and invalidate old live targets. Never reattach a running turn or replay a durable action ID. An unrelated world starts independent context by default; resuming older text must remain visibly historical.
- Keep close/open state separate from reply tasks and Stop. Persist read acknowledgements through a bounded versioned IPC change; heartbeat rewrites cannot create new unread replies. Test a completion racing with close, chat selection, reload, coordinator restart and display acknowledgement.
- Follow the migration with exact-source provider/native/player release gates. Prototype controls and mocks cannot replace migration/restart/failure tests or a working game-owned interface.

# Automatic candidate preference selection

The unshipped native panel now selects `AssistantScript.stateDirectory()` automatically when no developer preference-directory override is supplied. This is the assistant's existing configured state root, whose production owner already creates it; the candidate does not create a separate profile path or ask the player to attach/configure preferences. Its fixed `chat-layout.preferences` file holds only bounded geometry and palette fields. Different assistant state roots remain separate; these UI settings are not world/save identities.

Startup reads the existing version-1/version-2 preference formats through the same canonical-directory/regular-file checks. Missing files keep defaults and do not write anything. A valid automatic load restores geometry/style without rewriting the file or restoring a question draft. Explicit gesture drops, Reset layout and valid Style edits retain the existing private atomic-save behavior. Invalid/unavailable records keep the current layout and show the existing this-run/unavailable notice; automatic selection is not a guarantee that persistence succeeded. Initial malformed files are not silently overwritten. The developer startup property still takes precedence for controlled fixture runs.

[NATIVE_CHAT_AUTO_PREFERENCES_VALIDATION.json](NATIVE_CHAT_AUTO_PREFERENCES_VALIDATION.json) pins current sources/classes and two independent copied-game runs:

- Twenty-three native layout checks include automatic initial configuration without a preference property or manual configuration call, no file creation until an explicit edit, and a fresh own panel automatically restoring saved Night/#ABCDEF/640×560 with an empty composer and unchanged preference bytes. All prior layout/status/Style/draft/legacy/viewport/focus-marker checks pass again.
- Eleven actual helper/MCP/history notice phases start with automatic preference selection/configuration, then preserve the existing fake-inference/background/recovery behavior. Explicit Parchment/style and resize edits save to the fixture's assistant state root. File shape and private permissions are checked after native exit.

Each runner explicitly supplies a disposable assistant state root below repository `runtime/`; no normal player root is selected by these tests. The released player JAR does not contain this candidate change. The public own `AssistantScript.stateDirectory()` route is existing application code, not a new game getter or permanent world identifier. Historical [two-game-JVM preference evidence](NATIVE_CHAT_RESTART_VALIDATION.json) uses its explicitly overridden shared directory and retains that original scope; the new automatic path is tested across fresh own panels, not two game JVMs with one common state root.

The native internal viewport is 1536×768. Own primitive gestures and public own-widget routing are not physical input, screenshots, unobscured display, human readability, all-scene/scale/accessibility or receipts. No concurrent-game, hostile-filesystem-race, power-loss or universal save/load acceptance is implied. Full offline and unchanged source-matched current/previous ZIP checks are recorded. No paid calls, normal saves or credentials are changed; unknown/oversized replies remain unread. No badge, typed chips, gameplay action or redesigned player release is shipped.

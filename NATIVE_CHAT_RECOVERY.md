# Candidate same-history coordinator recovery

This developer-only fixture keeps one copied city and the current own chat overlay open while gracefully stopping its coordinator task, closing SQLite and constructing a new production Coordinator and SQLite connection against the same private history. The verifier process and stdio MCP session stay running. This is **not a helper-process, transport, abrupt-crash or interrupted-paid-turn recovery test**. No production source, tested player bundle, normal history, key or save is changed.

The initial seven native phases use the production simple coordinator/default 21-tool MCP, a disposable SQLite store and deterministic fake inference. They cover automatic loaded-game admission, style/resize/draft retention through a real partial frame, unpaused open/closed progression, closed completion, reopening the same chat and Stop on a second turn. One turn is completed and one cancelled; both fake providers are closed before recovery begins.

Two additional phases exercise the same-history path:

- With a new unsent draft in the native composer, the fixture requests graceful coordinator shutdown and reopens the same history through a new connection. The new coordinator initially has no selected chat. The native panel's existing automatic sync selects the persisted current-load chat again. The fixture waits for backend selection and the native action acknowledgement before checking the same composer/draft, transcript answer, style and geometry.
- After native recovery is acknowledged, the verifier parses and dispatches the original completed Send request with its original turn/action ID, question and runtime. The persistent action journal deduplicates it. No new task, turn or provider is created, and the native panel retains its chat/draft without entering generation. This replay is supplied by the fixed verifier through the production parser/dispatcher, not a physical UI retry or arbitrary game invocation.

[NATIVE_CHAT_RECOVERY_VALIDATION.json](NATIVE_CHAT_RECOVERY_VALIDATION.json) records all nine native checks, two actual reference calls with immutable citations, one final completed reply, one cancelled turn and exactly four fake-provider rounds across two providers. A provider-factory guard refuses any third instance, so replay cannot silently become new fake inference. Real model/network/billing behavior is not attested. A separate fresh seven-phase default background run checks that the shared fixture's recovery-disabled path still completes.

`dev/run_read_fixture.py --case layout-recovery` selects the fixed own class overlay and startup flag; `dev/verify_native_chat_recovery.py` invokes the shared verifier's explicit recovery mode. The normal production entry point, action protocol and database schema are unchanged. This case uses no preference-path override and no new world identity. The game stays in the same loaded runtime; the test does not switch worlds, replay private provider context or recover a running paid request.

Source/class hashes, clean completion, zero exit/no known crash markers, copied-mod restoration and copied-save integrity are recorded. Launcher/resize use supplied owned primitives and Send/Close/Stop use public own-widget routing. There is no OS input, pointer/button mutation, screenshot, pixel/read-receipt, physical focus or all-scene acceptance. Unknown/oversized display remains unread; no badge, typed chip or gameplay action is shipped.

The runner takes the machine-wide native fixture lock. The companion `layout-background` case retains its seven-phase behavior. Neither reads a provider credential or sends inference.

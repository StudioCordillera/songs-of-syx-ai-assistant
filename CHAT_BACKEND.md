# Experimental shared in-game chat

The development implementation now completes real two-turn game/tool/reference conversations through the same panel for **DeepSeek API** and **Claude subscription**, in separate chats. It adds private SQLite histories, rename/export/confirmed deletion, expandable evidence and explicit attachment after a copied-save reload. This does not complete every gate in [IN_GAME_CHAT.md](IN_GAME_CHAT.md): OpenAI sign-in, authenticated Claude API use, account setup entirely inside the game, proper multiline editing, physical keyboard testing and broader lifecycle/platform coverage remain pending.

## Player build

The [latest tested ZIP](https://github.com/StudioCordillera/songs-of-syx-ai-assistant/raw/refs/heads/main/releases/latest-user-test.zip) defaults to **DeepSeek Pro** (`deepseek-v4-pro`) and a simple panel enabled without extra Java flags. Follow [player setup](user_test/README.txt). It has separate saved chats, an automatically titled first question, a wrapped 240-character composer, Send/Stop and explicit attachment after loading another game. Provider selection, sign-in, evidence, export and deletion controls are hidden. Tool calls remain restricted read-only MCP queries; their raw evidence is stored privately rather than rendered in the transcript. The native text buffer reserves one character, so this input allocates 241 for 240 usable characters.

USER_TEST_VALIDATION.json records a real two-turn Pro check on the packaged source: three selected resource rows, retrieved guide citations and no tool JSON in the player transcript. It also records limitations. Historical CHAT_VALIDATION.json describes the older advanced UI, not acceptance of every current menu or physical keyboard behavior.

## Advanced development launch

Install the Python project in a virtual environment (`pip install -e '.[dev,claude]'`). The Claude extra pins the tested official Agent SDK. Install/authenticate the official Claude Code client for the subscription route; the coordinator uses its supported authentication rather than reading tokens itself. The tested client reported Claude Pro authentication. Eligibility, plan limits and extra-usage settings remain controlled by the provider/account. The plan notice linked in REFERENCES.md was reviewed for the historical authenticated checkpoint; recheck current account eligibility/policy before expanding that deferred route.

Use the same `SYX_STATE_DIR` as the game exporter. Supply DeepSeek credentials in the coordinator's environment or through a literal dotenv file:

```sh
syx-chat --advanced --state-dir "$SYX_STATE_DIR" --env-file /path/to/private/provider.env
```

`--env-file` reads exactly one `DEEPSEEK_API_KEY` entry without shell execution or interpolation. For explicit Claude API chats, `--claude-env-file` reads `ANTHROPIC_API_KEY` from a separate file (or use that environment variable). Missing Claude API credentials refuse the request; an existing subscription login is never a fallback. No real Anthropic API-key request has been validated yet. Credentials are not entered into chat, committed configuration or game launch arguments.

The coordinator merges 13 reviewed starter summaries automatically, preserving existing records and original retrieval dates. Installed game references remain separate and require no setup step. The corpus is small, version caveats remain explicit, and no live web crawl occurs.

The default history directory is `~/.local/share/syx-assistant-chat`, separate from game exports/saves. `--history-dir` overrides it. One coordinator owns it using a POSIX lock; Windows support is pending. Stop with Ctrl-C. Restart marks interrupted turns and never automatically resends them.

Build/install the development mod using [INSTALL.md](INSTALL.md). The simple panel is on by default. Disable with `-Dsyx.assistant.chat=false`; expose the developer panel with `-Dsyx.assistant.chat.advanced=true` and run the coordinator with `--advanced`. The panel offers **New DeepSeek**, **New Claude plan**, **New Claude API**, the chat list/transcript, Add text, Send, Stop, Evidence, Rename, Export, Confirm delete and Attach to this game. Each provider choice creates a separate chat; existing transcripts are not silently sent to another provider. New DeepSeek chats now use `deepseek-v4-pro`; new Claude chats use the explicit `haiku` alias. Other model selection in the panel is pending. The adapter/store also recognize the documented DeepSeek Pro identifier and Claude's Sonnet/Opus aliases; Pro is validated in USER_TEST_VALIDATION.json; Claude Sonnet/Opus choices are not independently validated here.

The single-line composer accepts short segments. Add text appends them into a draft up to 8000 characters; Send submits the draft plus current segment. The current composer names a new chat or renames the selected one. Chat selection clears an unsent draft. A running reply preserves the draft and refuses another Send. A reloaded game's chat requires explicit attachment; the draft is retained when this preflight rejects a send. This is a prototype interaction, pending proper multiline editing.

The transcript follows new output while at the bottom; scrolling upward preserves that position. Tool results are summarized by default; Evidence expands their bounded contents. The latest 100 events, per-event preview and rendered-row limits are labeled when truncated. Original bounded events remain in SQLite. Export writes a private JSON file under the history directory's `exports` folder (10000-event/10 MiB cap). Confirm delete removes the selected database chat; previous exports remain. There is no automatic retention policy or secure-erasure claim.

## Execution and credential boundaries

`syx_chat.py` runs the native DeepSeek conversation/tool loop. `syx_claude.py` provides the same conversation interface and history through an isolated official Agent SDK worker. Both require the same 13 read-only MCP tools, inspect fresh session identity before turns and observations, preserve bounded evidence/errors, and cap a turn at 180 seconds and sixteen tool calls. Each tool response is limited to 64 KiB. The SDK additionally caps itself at eight agentic turns and a USD 1 client-side cost estimate; this is not a guaranteed billing ceiling. Cancellation terminates the isolated SDK process group. Auth/quota/network errors never switch provider, account or billing route.

The SDK worker disables built-in tools, skills, project/user settings and other MCP servers, verifies the advertised tool set, and exposes only this bridge's read-only tools. Model requests have no shell, filesystem, native computer or gameplay-control tools. The worker receives only the selected route's credential context; unrelated API keys/provider overrides are removed. Subscription mode requires the official client's `claude.ai` authentication; API mode requires explicit API-key authentication. The SDK keeps its own tool-call IDs; the local transport records separate bridge-request IDs. See [the official SDK reference](https://code.claude.com/docs/en/agent-sdk/python).

DeepSeek's [thinking/tool protocol](https://api-docs.deepseek.com/guides/thinking_mode/) requires private continuation from prior assistant turns when tools are supplied. That stays in memory. Restart or failure discards it and logs a context reset; bounded visible history becomes historical data in a new context. Claude currently starts a new, explicitly logged SDK context each user turn with that chat's bounded visible history. Its within-turn private continuation is owned by the SDK. SDK session persistence is disabled. Neither mechanism claims exact provider-state restoration after restart.

The native DeepSeek adapter pins the official HTTPS endpoint and checks fragmented tool calls, streaming completion and response limits against the [chat completion reference](https://api-docs.deepseek.com/api/create-chat-completion/). Requests currently enable thinking/high effort and cap output at 8192 tokens. Ordinary query validation errors reach the model with actionable details; snapshot pins remain strict. Query help explains when to request a new atomic observation instead of pinning a snapshot that refreshes every two seconds.

The store uses SQLite transactions, foreign keys, UUID turn deduplication and user-only directory/database permissions. Events include provider/model/route, runtime session, timestamps and statuses. Configured credential strings are redacted, including across visible stream fragments; hidden reasoning and credential metadata are excluded. This does not detect every arbitrary secret pasted by a player. Local histories/exports contain plaintext private conversation/game evidence and are not encrypted. Unknown history schema versions fail explicitly.

The coordinator has no network listener. Its atomic file IPC has a durable admission journal; interrupted actions are not replayed automatically. Its MCP child receives no configured provider API keys. The optional Java panel uses separate source-verified public GUI widgets; existing game UI sections/popups are not replaced. GUI work stays on the update thread, while detached IPC strings use the existing I/O worker. It exports its own visibility, chosen provider/chat, generation and attachment state separately from game selection. A stopped coordinator is detected by heartbeat. These public widgets are source-verified, not established stable official contracts.

## Validation

[CHAT_VALIDATION.json](CHAT_VALIDATION.json) records four authenticated GUI turns across separate DeepSeek/Claude-subscription chats, successful three-row selections and cited guide URLs for both, with current JAR/source hashes. A separate copied-save test covers native game-menu coexistence, world/city transitions, reload identity, blocked pre-attachment sending, explicit attachment, rename/evidence/export/confirmed deletion. Offline tests cover SDK relay IDs, explicit API route/missing-key refusal and no provider fallback. Model prose is not the validation oracle: tool outcomes are checked independently. One earlier run answered via small reads after failed selections; it is not counted as a successful structured-query test.

Physical keyboard input, exhaustive modals/battle/generation states, standalone-main-menu hooks, broad performance and authenticated Claude API/OpenAI flows remain unverified. Earlier observation-only scene evidence in `validation-evidence.json` retains its own 0.12.0 build identity.

OpenAI registration/security and a mocked Responses transport are now [prepared](OPENAI_CONNECTION.md), with final account access approval and coordinator/model/UI wiring pending. Existing chats are not yet bound to a persistent account identity across credential changes; use a new chat/history for a different account until explicit account-switch handling is implemented. This remains an open AI-CHAT-014 gate.

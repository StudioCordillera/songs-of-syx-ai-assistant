# Collection diagnostics in selective results

Filtering, projection, grouping or joining game rows must preserve the observations' scan/failure/truncation limits. Each selective result's `sources` includes `collection_diagnostics`, scoped to that source and its requested node/ancestors. It contains only reviewed named Boolean/integer metadata; row values, exception strings, arbitrary nested objects and descendants are not copied into this metadata.

The housing integration experiment previously demonstrated seven omitted keys. The query engine now preserves `room_slots_scanned`, `room_map_size`, `scan_limit`, `room_scan_complete`, `failed_room_reads`, `failed_rosters` and `truncated_rosters`, alongside existing keys such as `row_limit`. Zero error counts and false completeness remain explicit. These names retain their source meaning; a complete slot scan does not establish that every room/roster read succeeded, and a row limit does not identify whether it was reached.

This is a Python metadata change. The game-facing Java source and every packaged Java class's content are unchanged. No new public game getter, writable tool, player housing table, native UI behavior or provider selection is introduced. Housing itself remains an unregistered candidate. The provisional candidate paths/examples are not current player query paths.

The repaired behavior has three new offline cases covering aggregate/join source provenance, zero/false preservation, and rejection of strings/containers/unrequested descendants. The full offline suite has 586 passing tests. [Native/MCP follow-up](HOUSING_QUERY_DIAGNOSTICS_VALIDATION.json) uses the same bounded developer-only augmented native snapshot as the earlier experiment: five actual stdio MCP calls check discovery, grouped totals, filtering/projection/order, raw data, snapshot/UI consistency, wrong-pin refusal and all eight capped scan/error/row diagnostics against the original candidate values. Its capped result explicitly carries `room_scan_complete=false`. This is not native nonzero roster-failure or complete production housing acceptance.

[USER_TEST_VALIDATION.json](USER_TEST_VALIDATION.json) records the exact current release's paid Pro/core/distribution checks and unchanged Java-class comparison. Earlier weather, cost, focus/background, tile/entity/regional and other feature reports retain their recorded JAR/Python/date scopes; they are not relabeled as fresh full-build tests. The latest and true previous tested player bundles remain the supported rollback pair.

Next housing work is mapping source-backed field/envelope meanings and bounded resident relationships into the production collector, followed by exact-source getter/DTO/MCP, fault/scene/discovery/cost and release gates. This diagnostic repair closes one prerequisite; it does not claim full variables, lifecycle, menu, reference or player-experience coverage.
